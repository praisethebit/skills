# Second review

   9. A fix for a review finding needs no new review. A code fix for a device-check failure needs one new review. Start it as in step 4.1, with one change to the prompt: in place of "Return the review output verbatim." write `Return verbatim only the findings whose file and line, or whose stated cause, are in this list: <each file and line range of the device-check fixes>. Then write one line with the count of the other findings and the file and line of each. If no finding is in the list, return NO FINDINGS and that line.` The arguments of the Skill call stay `medium <issue file path>`. Before the sort of step 4.5, drop each finding of this review that is not on a line of the list and does not name a line of the list as its cause. Count these drops, plus the count that the agent gives for the other findings, in the one line of dropped findings. Sort the other findings as in step 4.5, and fix each in-scope finding in this ticket. Start no third review: the full test run of step 4.8 and the device check are the proof of these fixes.

      Why: each review of the full change can find new points. A new review after each fix then has no end. The review reads the full change, and a rule in its arguments is not reliable, so the agent and the session apply the limit.
